# Homestead Animal Visibility v1

## Diagnóstico
El problema observado no apunta al `FarmLifecycleService`: las ovejas usan el runtime de `Pasture`, mientras Gallinas y Cuyes comparten el runtime/markers de `Homestead`. Si Sheep sí se ve y Chicken/Cuy no, el punto común es la colocación `AnimalSpawns`/`AnimalZones`, no la lógica de nacimiento.

Además, el `HomeService` actual tiene dos debilidades para un mapa que ha ido cambiando:

1. `ChickenSpawns` autogenerados se crean una vez y, si ya existen, `getOrCreateLogicalPart()` no actualiza su CFrame. Un marker `AutoGenerated` antiguo puede quedar en coordenadas obsoletas.
2. `CuySpawns` es opcional/manual; si falta o quedó mal colocado, el sistema no tiene una posición segura de fallback.

Este patch NO cambia reproducción, provisiones, IA, física, Fox, Pasture ni inventarios. Solo asegura posiciones de prueba visibles y válidas para Chicken/Cuy al arrancar Homestead.

El módulo contiene `TestVisiblePlacement = true` temporal y hace únicamente setup one-shot por casa:
- Chicken: 3 markers a ~7-9 studs del `CorralCenter`.
- Cuy: 2 markers a ~8 studs del `CorralCenter`.
- Cada marker se proyecta al suelo con UN raycast de setup desde +80 studs.
- El raycast excluye la casa y runtimes para no colocar animales sobre el techo ni sobre otros NPC.
- Crea `CuySpawns` si faltaba.
- Crea un `CuyRoamZone` fallback si faltaba.
- 0 loops, 0 Heartbeat, 0 RenderStepped.

## PATCH ÚNICO — HomeService.lua
Trabajar sobre el Source ACTUAL de Studio. NO reemplazar HomeService completo desde snapshots.

### 1. Require
Después de:
```lua
local StationService = require(script.Parent:WaitForChild("StationService"))
```
añadir:
```lua
local HomesteadAnimalPlacement = require(script.Parent:WaitForChild("HomesteadAnimalPlacement"))
```

### 2. Hook al final de `HomeService:EnsureHouseSetup`
La función actual termina aproximadamente con:
```lua
local _, chickenSpawns, cuySpawns, animalZones = self:EnsureAnimalFolders(house)
self:EnsureChickenSpawns(house, chickenSpawns)
self:EnsureCuySpawns(house, cuySpawns)
self:EnsureAnimalZones(house, animalZones)
```

Inmediatamente DESPUÉS añadir:
```lua
local placement = HomesteadAnimalPlacement.SyncHouse(house, HomeCfg)
if placement and HomeCfg.Debug and HomeCfg.Debug.PrintStartup then
	print(string.format(
		"[HomesteadAnimalPlacement] %s ChickenMarkers=%d CuyMarkers=%d",
		house.Name,
		placement.ChickenMarkers or 0,
		placement.CuyMarkers or 0
	))
end
```

No hacer ningún otro cambio a `HomeService.lua`.

## Por qué el hook va después
El setup normal de HomeService se conserva. Después, en modo de prueba, el helper recoloca/crea SOLO los markers necesarios antes de que `AnimalService` cree las instancias runtime. No modifica la IA ni mueve animales cada frame.

## Verificación local obligatoria antes de Play
En la casa que usará el jugador, comprobar que después del setup existen:

```text
HouseXX
└─ AnimalSpawns
   ├─ ChickenSpawns
   │  ├─ Spawn01
   │  ├─ Spawn02
   │  └─ Spawn03
   └─ CuySpawns
      ├─ Spawn01
      └─ Spawn02
```

Durante Play, los atributos de la casa deben mostrar:
- `AnimalVisibilityTestPlacement = true`
- `AnimalVisibilityChickenMarkers = 3`
- `AnimalVisibilityCuyMarkers = 2`

## Verificación runtime obligatoria
Después de reclamar casa y esperar ~3 s:

```text
Workspace
└─ HomeRuntime
   └─ Home_<UserId>
      └─ Animals
         ├─ Chickens  -> 3 Models iniciales
         └─ Cuys      -> 2 Models iniciales
```

Para CADA Model reportar:
- nombre
- `Model:GetPivot().Position`
- distancia al `CorralCenter`
- `AgeStage`
- `FarmSpecies`
- número de BaseParts visibles (`Transparency < 1`)

Condiciones de aceptación:
- Chicken inicial: 3 modelos, cada uno <= 20 studs del CorralCenter.
- Cuy inicial: 2 modelos, cada uno <= 20 studs del CorralCenter.
- cada modelo debe tener al menos 1 BasePart visible.
- no debe quedar ningún Chicken/Cuy bajo el suelo; pivot no más de 3 studs por debajo del ground hit usado para su marker.
